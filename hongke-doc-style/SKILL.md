# 鸿科文档风格（hongke-doc-style）

按鸿科品牌规范编写流程/SOP类文档与流程图。

## 工作方式（必须遵守）

1. **先研究**：读懂用户描述的流程，梳理主线逻辑、关键控制点和分歧点，先输出文字版理解。
2. **再讨论**：把模糊点、可选方案列给用户确认，不替用户做业务决策。
3. **确认后执行**：用户明确说方案OK，才开始产出文档/图片。
4. **业务规则每次重新梳理**：本技能只固化风格与框架，具体业务规则（公式、责任分工、时限）以当次用户确认内容为准，不沿用历史流程的规则。

## 品牌与样式规范

所有文档与流程图必须遵循 [references/brand-style.md](references/brand-style.md)：
- 配色、字体、表格样式、页眉页脚约定
- 流程图规范：白底、框内无填充、彩色边框+彩色文字、每个框标注责任人、450dpi 高清导出

## SOP 文档结构

SOP 类文档按 [references/sop-framework.md](references/sop-framework.md) 的章节框架组织：
目的 → 适用范围 → 术语与核心规则 → 流程图 → RACI矩阵 → 详细步骤（谁/何时/如何/产出）→ 异常与边界 → KPI指标 → 相关单据。

文档产出走 kimi-word 技能（docx-js 路线），构建后必须通过验证门与视觉检查再交付。

## 流程图脚本

用 [scripts/flowchart.py](scripts/flowchart.py) 生成流程图，不要从零写绘图代码：

```bash
python3 scripts/flowchart.py spec.json 输出路径.png
```

spec.json 定义画布、框（含责任人）、箭头、备注，脚本内置鸿科配色与白底无填充样式。spec 示例见脚本顶部注释。生成后打开图片检查文字不溢出、不重叠，再交付。
