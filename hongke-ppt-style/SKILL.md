# 鸿科 PPT 风格（hongke-ppt-style）

按鸿科品牌规范制作 PPT（安装/匹配说明书、测试结果说明、演示文档等）。

## 工作方式（必须遵守）

1. **先研究**：读懂用户提供的材料（数据、文档、风格基准 PPT），梳理内容逻辑和页面大纲，先输出文字版理解。
2. **再讨论**：把模糊点、可选方案（受众、页数、大纲、字体、背景素材）列给用户确认，不替用户做业务决策。
3. **确认后执行**：用户明确说方案 OK，才开始产出 PPT。此协议对 PPT 任务同样适用——2026-10-12 用户曾在 PPT 说明书任务中途叫停直接动手，重申"你先研究，然后我俩再讨论，我确定方案OK后，你再执行"。
4. **业务规则每次重新梳理**：本技能只固化风格与框架，具体业务规则（公式、责任分工、时限）以当次用户确认内容为准，不沿用历史任务的规则。

## 品牌与样式规范

版式、配色、字体、技术坑全部遵循 [references/brand-style-ppt.md](references/brand-style-ppt.md)：
- PPT 橙系配色常量（标题橙 `#E2931E`、序号块 `#E78F13`，与 docx 橙系不同值不要混用）
- 封面 / 章节页 / 内容页版式常量（16:9、黑体、橙色序号方块页眉）
- 构建技术规范：从零构建、字体节点 OOXML、照片预处理、章节页结构常量

## 制作流程

1. **先解析源 PPT，不凭截图猜**（用户提供风格基准文件时）：用 python-pptx 读出幻灯片尺寸、各页版式、字体字号、色值、背景图与 logo 素材，汇报研究结论和页面大纲，等用户确认（工作方式第 3 条）。
2. **风格常量**取自 [references/brand-style-ppt.md](references/brand-style-ppt.md)；若用户提供了新的鸿科 PPT 源文件，以从该文件解析出的值为准并更新该文件。
3. **从零构建**：python-pptx 标准模板（`slide_layouts[6]` 空白版式）从零构建，不依赖母版；禁止直接在 WPS 源文件上二次编辑（OOXML 节点不标准，会导致文件打不开，详见 brand-style-ppt.md 技术坑）。
4. **流程图必须原生形状**：PPT 里的流程图一律用 `scripts/pptx_flowchart.py` 生成原生可编辑形状，**禁止贴 PNG**（2026-10-18 起为强制规范，用户需求：做好的 PPT 要能直接编辑内容和元素）。
5. **照片素材预处理**：iPhone MPO 先转 JPEG；原图压缩到最长边 1600px（quality 82）；横竖版分别等比计算尺寸，避免变形。
6. **QA 自检**：逐页打开检查文字溢出、元素重叠；流程图页确认无整页贴图；有条件时渲染 PNG 逐页目检。

## 流程图脚本

用 [scripts/pptx_flowchart.py](scripts/pptx_flowchart.py) 生成 PPT 原生形状流程图，不要从零写形状代码：

```bash
python scripts/pptx_flowchart.py spec.json 输出.pptx
```

- spec.json 定义画布、框（标题/说明/系统环节）、箭头、备注，与 hongke-doc-style 技能 `flowchart.py`（PNG 版）格式一致，示例见脚本顶部注释
- 输出文件不存在：新建只有该流程图页的单页 16:9 文稿；已存在（python-pptx 从零构建的主文档）：追加一页（非 16:9 会拒绝，防止版式错乱）
- 框 = 白底圆角矩形 + 彩色边框，三行文字（标题彩色加粗 / 说明中灰 / 环节或责任人彩色加粗）可直接编辑；箭头 = 连接线 + 三角箭头，回退弧线 = 贝塞尔 freeform；配色内置鸿科规范
- 自动生成 `输出.预览.png`（复用 hongke-doc-style 的 flowchart.py 渲染），检查文字不溢出、不重叠后交付，预览图可删
